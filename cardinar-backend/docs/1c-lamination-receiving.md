# Приёмка на склад ламинации по «Заказу на перемещение» из 1С

Документ для программиста 1С. Описан обмен между 1С и Cardinar по приёмке сырья ламинации.

Порядок работы:

1. 1С присылает «Заказ на перемещение». В Cardinar он получает статус «Ожидается приёмка».
2. Кладовщик ламинации создаёт и проводит в Cardinar «Приходный ордер на товары» с фактически принятым количеством. Можно принять только часть.
3. Кладовщик раскладывает принятое по ячейкам и проводит «Размещение (отбор) товаров».
4. Проведённый ордер и проведённое размещение попадают в очередь обмена. 1С забирает их из очереди и подтверждает (ack).

Все примеры ниже выполнены на тестовом сервере 16.10.2026, ответы взяты из реального прогона. В примерах ответов часть полей сокращена: место пропуска отмечено `…`.

## Авторизация

- 1С работает через сервисный аккаунт с ролью `integration1c`. Ключ передаётся в заголовке `x-api-key: <ключ>`. Ключ выдаётся один раз через защищённый канал. Писать его в чат или в код нельзя.
- Тело запроса — JSON в UTF-8, заголовок `content-type: application/json`. Если у POST нет тела, отправляйте `{}`.
- Можно указывать адреса с префиксом `/api/v1/…`: это то же самое, что `/api/…`.
- Если ключ неверный, сервер вернёт `401 {"error":"Неверный API-ключ","code":"UNAUTHORIZED"}`.

## Количества

Количество передаётся строкой или числом. Допускается не более 3 знаков после точки, разделитель — точка: `"500.250"`, `"100"`. Сервер хранит количество в формате NUMERIC(18,3) и всегда отдаёт строкой с тремя знаками после точки: `"100.000"`. Округления нет: если знаков больше трёх, сервер вернёт 400.

## 1. Заказ на перемещение (1С → Cardinar)

`POST /api/v1/inbound/lamination/transfer-orders`

Запрос работает как upsert по `external_id`, то есть по идентификатору документа в 1С (GUID или другой постоянный id).

```json
{
  "external_id": "9f1c2a7e-0001",
  "number": "ЗП-000123",
  "date": "2026-10-16",
  "sender":    { "kind": "supplier", "external_id": "SUP-77", "name": "Zhejiang Film Co" },
  "warehouse": { "external_id": "WH-LAM", "name": "Склад ламинации" },
  "truck":     { "number": "01A777AA", "arrival_date": "2026-10-18" },
  "lines": [
    { "line_id": "1",
      "item": { "external_id": "N-PET", "sku": "PET-12", "name": "Плёнка ПЭТ 12 мкм",
                "barcode": "4600000000011", "series": "S-1", "unit": "кг" },
      "qty": "500.250", "weight": "500.250", "volume": "0.8" },
    { "line_id": "2",
      "item": { "external_id": "N-GLUE", "sku": "GL-1", "name": "Клей ПУ", "unit": "кг" },
      "qty": "100" }
  ]
}
```

Обязательные поля: `external_id`, `lines[]`, а в каждой строке — `line_id`, `item.external_id` и `qty > 0`. `line_id` — постоянный id строки в 1С, он должен быть уникален внутри заказа. Например, это может быть номер строки табличной части, если 1С не перенумеровывает строки. Поле `sender.kind` принимает значения `supplier` или `warehouse`. Если `unit` не указан, подставляется `кг`.

Ответы:

| Ситуация | Код | `result` |
|---|---|---|
| Новый заказ | 201 | `created` |
| Повтор с тем же телом | 200 | `unchanged`: дублей нет, данные не меняются |
| Изменённый заказ | 200 | `updated` |

```json
HTTP 201
{"result":"created","order":{"id":"LTO-d307c950","external_id":"9f1c2a7e-0001","number":"ЗП-000123",
 "status":"Ожидается приёмка","status_text":"Ожидается приёмка", …,
 "lines":[{"id":"LTL-55287323","line_id":"1","item_external_id":"N-PET","series":"S-1","unit":"кг",
           "planned_qty":"500.250","received_qty":"0.000","remaining_qty":"500.250", …}, …]}}
```

Правила изменения заказа:

- Можно менять шапку, добавлять строки и менять план.
- Нельзя опустить план строки ниже уже принятого количества. Сервер вернёт `409 PLAN_BELOW_RECEIVED`:
  ```json
  HTTP 409
  {"error":"Строка 1: план 200 меньше уже принятого 300.125","code":"PLAN_BELOW_RECEIVED"}
  ```
- Нельзя удалить строку, по которой уже есть приходный ордер. Сервер вернёт тот же код `409 PLAN_BELOW_RECEIVED`.
- Отменённый заказ изменить нельзя: `409 ORDER_CANCELLED`.
- При ошибке ничего не применяется: изменение заказа выполняется одной транзакцией.

### Массовая загрузка

Тот же адрес принимает тело вида `{"orders":[{…},{…}]}`. Каждый заказ обрабатывается отдельно. Ответ всегда `200`:

```json
{"results":[
  {"external_id":"9f1c2a7e-0001","status":200,"result":"unchanged","order_id":"LTO-…","order_status":"Ожидается приёмка"},
  {"external_id":"9f1c2a7e-0002","status":409,"result":"rejected","code":"PLAN_BELOW_RECEIVED","error":"…"}
]}
```

### Отмена заказа

`POST /api/v1/inbound/lamination/transfer-orders/{external_id}/cancel`, тело `{}`.

- Ответ `200 {"order":{…,"status":"Отменён"},"idempotent":false}`. Повторная отмена вернёт `idempotent: true`.
- Если по заказу уже проведён приходный ордер, отменить его нельзя:
  ```json
  HTTP 409
  {"error":"По заказу уже проведены приходные ордера, отменить нельзя","code":"HAS_RECEIPTS"}
  ```

### Статусы заказа

| Статус | Когда ставится |
|---|---|
| `Ожидается приёмка` | ничего не принято |
| `Частично получено` | принята часть. В `status_text` выводится «Частично получено 400.125 из 600.250 кг». Если у строк разные единицы, выводится «строк N из M» |
| `Получен полностью` | по всем строкам принятое количество равно плану |
| `Отменён` | заказ отменён из 1С |

## 2. Результаты для 1С (Cardinar → 1С)

После проведения в очередь обмена ставятся операции двух видов:

| `kind` | `op_id` | Когда появляется |
|---|---|---|
| `lamination_receipt` | id приходного ордера, `LRO-…` | после проведения приходного ордера |
| `lamination_placement` | id размещения, `LPL-…` | после проведения размещения |

Операции появляются в очереди со статусом `подготовлено`. Чтобы забрать их, отправьте запрос:

`GET /api/v1/exchange?kind=lamination_receipt&status=подготовлено`

Значение статуса в URL кодируйте в UTF-8. Дополнительно можно указать `since=<ISO-время>`: тогда вернутся только операции с `updated_at` позже этого времени.

```json
HTTP 200
{"exchange":[{"op_id":"LRO-befe755c","kind":"lamination_receipt","status":"подготовлено",
  "payload":{"type":"lamination_receipt","receipt_id":"LRO-befe755c",
    "order_external_id":"9f1c2a7e-0001","order_number":"ЗП-000123","order_status":"Частично получено",
    "in_doc_number":"CMR-55","in_doc_date":"2026-10-18","responsible":"Кладовщик ламинации","comment":null,
    "posted_at":"2026-10-16T06:46:59.415Z","posted_by":"lamsklad",
    "lines":[{"line_id":"1","item_external_id":"N-PET","sku":"PET-12","name":"Плёнка ПЭТ 12 мкм",
              "barcode":"4600000000011","series":"S-1","unit":"кг","qty":"300.125"},
             {"line_id":"2","item_external_id":"N-GLUE","sku":"GL-1","name":"Клей ПУ",
              "barcode":null,"series":"","unit":"кг","qty":"100.000"}]},
  "doc_number":null,"doc_date":null, …}]}
```

По одному заказу может прийти несколько приходных ордеров, по одному на каждую фуру. Каждый ордер содержит только количество, принятое этим ордером, а не нарастающий итог. Строки ордера сопоставляются со строками заказа по паре `order_external_id` + `line_id`.

Payload размещения устроен так: `{"type":"lamination_placement","placement_id":"LPL-…","receipt_id":"LRO-…","order_external_id":"…","lines":[{"line_id":"1","item_external_id":"N-PET","series":"S-1","unit":"кг","cell":"1-А-1","qty":"200.100"}, …]}`. Одна строка ордера может быть разложена по нескольким ячейкам. Ячейка записывается в формате ряд-стеллаж-полка, например `1-А-1`. Сервер хранит её в верхнем регистре.

Одну операцию можно получить по её `op_id`: `GET /api/v1/exchange/{op_id}`.

### Подтверждение (ack)

`POST /api/v1/exchange/{op_id}/ack`

Успешное проведение в 1С:

```json
{"status":"принято 1С","doc_number":"0000-000777","doc_date":"2026-10-18"}
```
```json
HTTP 200
{"exchange":{"op_id":"LRO-befe755c","status":"принято 1С","doc_number":"0000-000777","doc_date":"2026-10-18", …},"idempotent":false}
```

- Повторный ack с тем же статусом вернёт `200` и `"idempotent": true`.
- Если 1С не смогла провести документ, отправьте `{"status":"ошибка","error":"нет номенклатуры N-PET","code":"ITEM_NOT_FOUND"}`. Поле `error` обязательно. После исправления можно снова отправить `принято 1С`.
- Операцию, уже принятую 1С, изменить нельзя: `409 INVALID_STATUS`.
- Если операции нет: `404 NOT_FOUND`. Если статус неверный или при ошибке не указан `error`: `400 VALIDATION_ERROR`.

Номер документа 1С виден кладовщику в карточке ордера. Статус обмена отображается в поле `exchange_status`.

## 3. Коды ошибок

| HTTP | `code` | Значение |
|---|---|---|
| 400 | `VALIDATION_ERROR` | нет обязательного поля, неверное количество или формат ячейки, неизвестный статус в фильтре |
| 400 | `SUM_MISMATCH` | сумма по ячейкам не равна принятому количеству строки (размещение) |
| 401 | `UNAUTHORIZED` | нет ключа или ключ неверный |
| 403 | `FORBIDDEN` | у роли нет права. Например, `integration1c` не может проводить ордер и размещение, это делает только кладовщик |
| 404 | `NOT_FOUND` | заказ, ордер, размещение или операция обмена не найдены |
| 409 | `PLAN_BELOW_RECEIVED` | план ниже принятого или удаляется строка, по которой есть приём |
| 409 | `ORDER_CANCELLED` | заказ отменён |
| 409 | `HAS_RECEIPTS` | отмена заказа, по которому уже есть проведённые ордера |
| 409 | `OVER_PLAN` | приём больше остатка к приёму. Ответ получает кладовщик, не 1С |
| 409 | `RECEIPT_NOT_POSTED`, `PLACEMENT_EXISTS` | размещение по непроведённому ордеру; повторное размещение |
| 409 | `INVALID_STATUS` | недопустимый переход статуса обмена |

Тело ошибки всегда имеет вид `{"error":"<текст по-русски>","code":"<код>"}`.

## 4. Справка: API кладовщика (не для 1С)

Для этих запросов нужен вход по логину и паролю (`POST /api/login`) и заголовок `authorization: Bearer <token>`. Роль `laminationStorekeeper` может всё, `director` — только читать.

| Метод и адрес | Что делает |
|---|---|
| `GET /api/lamination/transfer-orders?status=…` | список заказов |
| `GET /api/lamination/transfer-orders/{id или external_id}` | карточка заказа: строки с `remaining_qty` и список ордеров |
| `POST /api/lamination/receipt-orders` | создать черновик ордера. Тело: `{order_id, in_doc_number, in_doc_date, responsible?, comment?, lines:[{order_line_id, qty}]}` |
| `POST /api/lamination/receipt-orders/{id}/post` | провести ордер. Строки заказа блокируются (FOR UPDATE), поэтому два кладовщика не могут вместе принять больше плана |
| `GET /api/lamination/receipt-orders/{id}` | карточка ордера |
| `POST /api/lamination/placements` | создать размещение. Тело: `{receipt_id, lines:[{receipt_line_id, cell, qty}]}`. Одно размещение на ордер |
| `POST /api/lamination/placements/{id}/post` | провести размещение. После этого товар попадает в остаток ячейки |
| `GET /api/lamination/placements/{id}` | карточка размещения |
| `GET /api/lamination/cell-stock?cell=&item=` | остатки по ячейке, номенклатуре и серии |
| `GET /api/lamination/cells`, `POST /api/lamination/cells {code}` | справочник ячеек: заданные вручную и уже использованные |
