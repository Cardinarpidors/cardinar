# Заказы-конвейеры из 1С

Документ для программиста 1С. Здесь описано, как 1С передаёт в Cardinar заказы-конвейеры (партии кроя вида T541).

Термины:

- **Заказ-конвейер** — документ 1С, например T541.
- **Позиция** — одна строка заказа, то есть один комплект. Пример позиции: чехол на машину. В позиции указан план в комплектах.
- **Спецификация позиции** — что нужно на один комплект:
  - детали кроя (передняя спинка, задняя спинка, боковина…) и сколько штук каждой детали идёт на комплект;
  - аксессуары (нитки, замки…) и их количество на комплект.

Комплект считается готовым, когда вырезаны все его детали. Сколько комплектов готово по позиции, Cardinar считает сам: для каждой детали делит вырезанное количество на количество на комплект с округлением вниз и берёт наименьшее из этих чисел.

## Авторизация

Авторизация такая же, как в обмене по ламинации (`docs/1c-lamination-receiving.md`):

- Запросы идут от сервисного аккаунта с ролью `integration1c`.
- Ключ передаётся в заголовке `x-api-key: <ключ>`. Ключ выдаётся один раз через защищённый канал. Не пишите его в чат и в код.
- Тело запроса — JSON, `content-type: application/json`. Если у POST нет тела, отправляйте `{}`.
- Если ключ неверный, сервер отвечает `401 {"error":"Неверный API-ключ","code":"UNAUTHORIZED"}`.

Базовый адрес: `https://production-accounting-1c-demo.cloudplus.uz/api/cardinar/v1`

## 1. Заказ-конвейер (1С → Cardinar)

`POST https://production-accounting-1c-demo.cloudplus.uz/api/cardinar/v1/inbound/production-orders`

```json
{
  "external_id": "1C-PO-0001",
  "number": "T541",
  "date": "2026-10-19",
  "status": "В работе",
  "comment": "Октябрь, свои",
  "items": [
    {
      "line_id": "1",
      "sku": "CH-CAMRY-BLK",
      "name": "Чехол Camry 70 чёрный",
      "qty": 20,
      "parts": [
        { "name": "Передняя спинка", "qty": 2 },
        { "name": "Задняя спинка", "qty": 1 },
        { "name": "Боковина", "qty": 4 }
      ],
      "accessories": [
        { "name": "Нитки чёрные", "qty": "0.5", "unit": "катушка" },
        { "name": "Замок 55 см", "qty": 2, "unit": "шт" }
      ]
    }
  ]
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `external_id` | да | Уникальный id документа в 1С (например, GUID). По нему повторная отправка распознаётся как тот же заказ. |
| `number` | да | Номер конвейера, например `T541`. |
| `date` | нет | Дата заказа. |
| `status` | нет | Статус в 1С, по умолчанию `Новый`. Статус `Отменён` в этом поле передать нельзя: для отмены есть отдельный запрос `/cancel`. |
| `comment` | нет | Комментарий. |
| `items[].line_id` | да | id строки в 1С. В пределах заказа не должен повторяться. |
| `items[].sku`, `items[].name` | хотя бы одно | Артикул и название позиции. |
| `items[].qty` | да | План в комплектах: целое число больше 0. |
| `items[].parts[]` | да, хотя бы одна | Деталь кроя: `name` — название, уникальное внутри позиции; `qty` — штук на один комплект, целое число больше 0. |
| `items[].accessories[]` | нет | Аксессуар: `name`, `qty` на один комплект (больше 0, не больше 3 знаков после точки, разделитель — точка), `unit` (по умолчанию `шт`). |

Ответы:

- `201 {"result":"created","order":{…карточка…}}` — заказ создан.
- `200 {"result":"unchanged",…}` — пришло то же самое, что уже сохранено. Дубля не будет, повторять отправку можно сколько угодно.
- `200 {"result":"updated",…}` — заказ изменился. Шапка, позиции и спецификация заменяются целиком тем, что прислали.

Можно отправить несколько заказов одним запросом: `{"orders":[{…},{…}]}`. Ответ: `200 {"results":[{"external_id","status","result","order_id","order_status"}…]}`. Ошибочный заказ получит `"result":"rejected"` с полями `code` и `error`, остальные заказы пачки при этом сохраняются.

## 2. Отмена

`POST https://production-accounting-1c-demo.cloudplus.uz/api/cardinar/v1/inbound/production-orders/{external_id}/cancel`, тело `{}`.

- `200 {"order":{…,"status":"Отменён"},"idempotent":false}` — заказ отменён.
- Повторная отмена возвращает `"idempotent":true`.

## Ошибки

Тело ответа при ошибке: `{"error":"<текст по-русски>","code":"<КОД>"}`.

| HTTP | code | Когда |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Не заполнено обязательное поле, повторяется `line_id` или деталь, количество 0 или дробное и т. п. В тексте ошибки указаны номер позиции и поле, например `Позиция 1: qty - количество комплектов, целое число больше 0`. |
| 401 | `UNAUTHORIZED` | Нет ключа или ключ неверный. |
| 403 | `FORBIDDEN` | Ключ не от роли `integration1c`. |
| 404 | `NOT_FOUND` | Отменяют заказ с неизвестным `external_id`. |
| 409 | `HAS_MOVEMENTS` | По заказу уже начат крой, выданы аксессуары или комплекты переданы швеям. Менять состав заказа и отменять его нельзя. |
| 409 | `ORDER_CANCELLED` | Пытаются изменить отменённый заказ. |

## Карточка конвейера (для справки)

`GET /api/cardinar/v1/production-orders/{id или external_id}` — запрос для пользователей Cardinar, ключ 1С здесь не нужен. По каждой позиции карточка показывает:

- `planned_kits` — план в комплектах;
- `ready_kits` — готово комплектов;
- `accessories_issued_kits` — на сколько комплектов выданы аксессуары;
- `handed_to_sewing_kits` — сколько комплектов передано швеям.

По каждой детали карточка показывает `qty_per_kit`, `planned_qty`, `cut_qty` (вырезано) и `kits_cut`. Кроме того, карточка показывает `overcut_qty` по детали и `overcut` по позиции (вырезано больше плана), `accessories_available_kits`, `in_transit_kits` и `handover_available_kits`.

## Передача комплектов швеям (Cardinar → 1С): операция `sewing_handover`

Когда руководитель швей нажимает «Получил», в очередь обмена ставится операция `sewing_handover`. Для 1С это документ «Перемещение товаров» со склада кроя (или лазера) на склад швейного цеха. Одна операция соответствует одной передаче, то есть одной позиции конвейера. В операцию попадает фактически полученное количество комплектов. Если швеи получили 0 комплектов, операция не создаётся.

### Получить

`GET /api/cardinar/v1/exchange?kind=sewing_handover&status=подготовлено`, заголовок `x-api-key: <ключ integration1c>`.

```json
{"exchange":[{"op_id":"POH-3f1a9c2e","kind":"sewing_handover","status":"подготовлено","payload":{
  "handover_id":"POH-3f1a9c2e","document":"Перемещение товаров",
  "order_external_id":"1C-KF-0001","order_number":"T600",
  "source":"cut","warehouse_from":"CUT","warehouse_to":"SEWING",
  "sent_by":"lamhead","sent_at":"2026-10-19T09:10:00Z","received_by":"shveya","received_at":"2026-10-19T09:40:00Z",
  "items":[{"line_id":"1","sku":"CH-CAMRY","name":"Чехол Camry","kits":3,"kits_sent":4,
    "discrepancy_reason":"один комплект без боковины",
    "parts":[{"name":"Передняя","qty":6},{"name":"Задняя","qty":3},{"name":"Боковина","qty":12}],
    "accessories":[{"name":"Нитки","unit":"катушка","qty":"1.500"},{"name":"Замок","unit":"шт","qty":"6.000"}]}]}}]}
```

| Поле | Что означает |
|---|---|
| `source` | `cut` — крой цеха ламинации, `laser` — лазерный крой в швейном цехе. |
| `warehouse_from`, `warehouse_to` | Коды складов в 1С. **Требуют согласования.** Сейчас стоят условные значения `CUT`, `LASER` и `SEWING`; после согласования их заменят на настоящие коды. |
| `items[].kits` | Сколько комплектов получили швеи. Это количество документа. |
| `items[].kits_sent` | Сколько комплектов отправили. Если отправили больше, чем получили, причина указана в `discrepancy_reason`. |
| `items[].parts[].qty` | Количество деталей: `kits` × количество деталей на один комплект. |
| `items[].accessories[].qty` | Количество аксессуаров: `kits` × количество на один комплект, до 3 знаков после точки. |

Одну операцию можно получить по `op_id`: `GET /api/cardinar/v1/exchange/{op_id}`.

### Подтверждение (ack)

`POST /api/cardinar/v1/exchange/{op_id}/ack`

- Документ проведён: `{"status":"принято 1С","doc_number":"0000-000042","doc_date":"2026-10-19"}`.
- Документ не проведён: `{"status":"ошибка","error":"<текст>","code":"<код>"}`.

Ответ: `{"exchange":{…,"status":"принято 1С","doc_number":"0000-000042"},"idempotent":false}`. Если повторить ack с тем же статусом, вернётся `"idempotent":true`. Операцию, которую 1С уже приняла, изменить нельзя: ответ `409 INVALID_STATUS`. Номер документа 1С виден в передаче (поля `doc_number_1c` и `exchange_status`).

### Справка: API конвейера (не для 1С)

| Запрос | Кто | Что делает |
|---|---|---|
| `POST /production-orders/{id}/items/{line_id}/cut` `{"parts":[{"name","qty"}],"op_id"?}` | laminationHead (`source=cut`), laserResponsible (`source=laser`) | Записывает крой. Вырезать больше плана можно, перерасход помечается в карточке. |
| `GET /production-orders/{id}/cut-log` | все роли конвейера | Журнал кроя: кто, когда, источник. |
| `POST /production-orders/{id}/items/{line_id}/accessories` `{"kits"}` | embroidery | Выдаёт аксессуары. Должно выполняться: `kits` ≤ `accessories_available_kits`. |
| `POST /production-orders/{id}/items/{line_id}/handover` `{"kits"}` | laminationHead, laserResponsible | «Передал»: передача получает статус «В пути». Должно выполняться: `kits` ≤ `handover_available_kits`. |
| `POST /production-orders/handovers/{id}/accept` `{"kits","reason"?}` | sewingHead | «Получил». Если получено меньше отправленного, нужна причина. |
| `GET /production-orders/{id}/handovers` | все роли конвейера | Список передач со статусом обмена и номером документа 1С. |
