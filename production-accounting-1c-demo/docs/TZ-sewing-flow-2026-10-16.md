# ТЗ Cardinar — цех вышивки, цех пошива и адресный склад сырья, 16.10.2026

Источник: созвон с Романом Юлдашевым в Telegram 16.10.2026, уточнён по 5 пунктам
по ходу разговора и сверен с реальной системой клиента tikuv.taskbot.uz (конвейеры,
qator, ячейки, расход, приёмка), чтобы термины совпадали с тем, что уже знают сотрудники.

## 1. О чём документ

Сейчас в демо Cardinar реализован только один участок — склад и цех ламинации
(приёмка сырья с фуры по приходным ордерам 1С, частичный приём, ячейки, передача
в цех, расход и выпуск). Этот документ описывает вторую половину цепочки: цех
вышивки (аксессуары), цех пошива (куда стекается выпуск обоих цехов) и отдельный
адресный склад сырья с выдачей строго по запросу.

## 2. Роли

| Роль | Что делает |
|---|---|
| Оператор цеха вышивки | Берёт задание-комплект (конвейер), фиксирует расход и выпуск аксессуаров, отправляет готовое в цех пошива |
| Оператор ламинации | Тот же процесс, но для раскроя (уже реализовано ранее) |
| Начальник цеха (вышивка/ламинация) | Видит оба цеха разом, сверяет: хватает ли выпущенного на план по комплектам |
| Начальник швейного цеха | Третий цех — принимает выпуск от вышивки и ламинации, повторно сверяет и подтверждает приёмку |
| Кладовщик сырья (адресный склад) | Хранит сырьё по ячейкам (ряд-стеллаж-полка, формат `1-А-1`), выдаёт только по запросу цеха, не решает сам кому сколько |
| Аналитик (1С, вне Cardinar) | Создаёт задания-комплекты: сколько произвести, на какие машины/линии — это и есть план, который видят цеха |

## 3. Как устроен процесс

### 3.1. Задание на комплект приходит из 1С

Аналитик в 1С указывает: произвести N комплектов определённой модели. В Cardinar
это задание появляется как карточка с ID конвейера (например `T541`) — он же
используется везде дальше как сквозной идентификатор партии, по нему ищут
изделие на любом этапе.

### 3.2. Склад сырья — выдача только по запросу, двойное подтверждение

Склад не выдаёт материал сам по себе. Цепочка:
1. Сотрудник цеха создаёт заявку на материал (конвейер, что нужно, сколько).
2. Кладовщик видит заявку, готовит материал, нажимает **«Передал»** — в этот
   момент автоматически формируется документ расхода (кто выдал, что, сколько,
   по какому конвейеру, когда) — журнал, который можно фильтровать по конвейеру
   или по материалу.
3. Сотрудник цеха нажимает **«Забрал»** — только после этого заявка считается
   закрытой. Без второго подтверждения выдача не завершена.

### 3.3. Цех вышивки и цех ламинации — расход и выпуск

Каждый цех списывает сырьё и фиксирует выпуск готовых деталей по заданию-
конвейеру. Начальник цеха (один на оба направления) видит сводную таблицу:
план по комплектам vs фактический выпуск вышивки vs фактический выпуск
раскроя — сразу понятно, хватает ли на план.

### 3.4. Передача в цех пошива — перемещение в 1С только после приёмки

Это ключевое правило, ради которого всё затевалось:
- Когда цех (вышивка или ламинация) нажимает **«Выпуск готов»**, запись
  переходит в статус **«В пути»**. Остаток при этом **не списывается** у
  цеха-отправителя — он продолжает числиться за ним.
- Только когда начальник швейного цеха нажимает у себя **«Всё получено»**,
  происходит фактическое перемещение остатка, статус становится **«Получено»**.
  До этого момента в 1С перемещения быть не должно.

Это сделано по аналогии с уже работающей частичной приёмкой на складе
ламинации: заказ висит в «ожидающих», пока не закрыт полностью.

### 3.5. Поиск по конвейеру

ID конвейера — сквозной идентификатор партии. Поиск по нему работает на всех
новых экранах (вышивка, приёмка на пошив, заявки на материал, журнал расхода) —
фильтр по тексту, учитывает частичное совпадение.

## 4. Термины клиента → термины в системе

| Как называет клиент / tikuv-tizim | Что это в Cardinar |
|---|---|
| Конвейер (konveyer) | ID партии-задания на комплект, например `T541` — не физическая линия |
| Qator | Физический ряд/рабочее место в цеху (в демо не реализовывали — не требовалось для этой части ТЗ) |
| Приходный ордер (pryomka) | Задание-комплект из 1С — аналог уже реализованных приходных ордеров в приёмке ламинации |
| Ячейка `1-А-1` | Ряд-стеллаж-полка адресного хранения — формат сохранён как у клиента |
| Расход (rasxod) | Документ расхода, создаётся автоматически при выдаче со склада («Передал») |

## 5. Что сделано в демо (проверено вживую в браузере 16.10.2026)

- Два цеха-отправителя (вышивка, ламинация) с этапом расход+выпуск и сверкой
  у общего начальника.
- Третий цех (пошив) с отдельной ролью начальника, который принимает и
  повторно сверяет.
- Адресный склад сырья: заявка → «Подготовить» → «Передал» (документ расхода
  формируется автоматически) → «Забрал» (выдача закрыта).
- Поиск по ID конвейера на всех перечисленных экранах.
- Статусная модель «В пути / Получено» с реальным переносом остатка только
  после подтверждения приёмки.
- Сквозной сценарий пройден в браузере на проде: T541 от заявки до приёмки на
  пошиве, журнал расхода, двойное подтверждение склада — без ошибок в консоли.

## 6. Что не входило в этот круг вопросов

- Отдельный Telegram-бот интерфейс для рядовых сотрудников — у клиента уже
  есть готовый бот (tikuv-tizim), дублировать в веб-демо не просили.
- Физические ряды (qator) как отдельная сущность — в этой итерации не нужны,
  Cardinar оперирует только конвейером как ID партии.
- Реальная синхронизация с 1С и с tikuv-tizim (API) — демо работает на
  локальных мок-данных, как и остальной Cardinar.
